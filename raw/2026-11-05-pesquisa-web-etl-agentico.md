- Qlik: ETL agêntico = agentes autônomos usam raciocínio multi-etapa para construir, rodar e reparar pipelines. — https://www.qlik.com/us/agentic-etl
- Integrate.io: arquitetura em camadas — percepção (metadados, observabilidade), motor de raciocínio (LLM), framework de ações permitidas (retry de jobs, ajuste de schema). Cita disponibilidade de 95% → 99,5% sem fonte nomeada. — https://www.integrate.io/blog/agentic-data-pipelines/
- BlueOrange: remediação autônoma é onde esses sistemas costumam quebrar; recomenda retries limitados para falhas recuperáveis (rate limit, mudança transitória de schema); retries de chamadas LLM podem estourar custo. — https://blueorange.digital/blog/agentic-data-pipelines-what-actually-runs-in-production/
- CloverDX: não rodar LLM por registro (caro e mais lento que lógica determinística); exemplo: SQL marca transações suspeitas, LLM só descreve as anomalias; logar todo prompt e resposta para depuração e revisão. — https://www.cloverdx.com/blog/using-llms-in-etl-pipelines-production-scale-best-practices
- Al-Kindi (JCSTS, 2025): artigo acadêmico sobre agentes de IA para pipelines self-healing (achados não lidos). — https://al-kindipublisher.com/index.php/jcsts/article/view/9427
- Lyzr: self-healing como recurso de produto (marketing). — https://www.lyzr.ai/ai-agents/ai-agents-for-etl-automation/
- N-iX: ETL agêntico = agentes interpretam objetivos de engenharia de dados, planejam e executam multi-etapa. — https://www.n-ix.com/agentic-etl/
- Airbyte: ETL para IA em infraestrutura agêntica. — https://airbyte.com/agentic-data/etl-for-ai
